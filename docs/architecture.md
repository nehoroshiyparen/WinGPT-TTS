# Структура и разработка

Приложение устанавливается как пакет `wgtts`. Модули используют импорты из пакета,
а тесты и инструменты — установленную версию. Ручного изменения `sys.path` нет.

## Части приложения

| Модуль | Ответственность |
| --- | --- |
| `wgtts.cli` | Аргументы запуска и выбор интерактивного / одноразового режима |
| `wgtts.chat.models` | Сообщения, снимки интерфейса и результаты сбора |
| `wgtts.chat.reader` | Адаптер Windows UI Automation для ChatGPT |
| `wgtts.chat.history` | Объединение сообщений и хранение истории |
| `wgtts.chat.scanner` | Полное чтение чата с прокруткой и отменой |
| `wgtts.chat.watcher` | Обнаружение новых завершённых ответов |
| `wgtts.speech.applio` | HTTP API, задачи синтеза и очистка своих временных файлов |
| `wgtts.speech.playback` | WAV, PCM, громкость и остановка звука |
| `wgtts.speech.service` | Очередь озвучки, отмена и смена состояний |
| `wgtts.ui.terminal` | Выполнение команд и связь истории, озвучки и интерфейса |
| `wgtts.ui.console` | Экран консоли, ввод, вывод и возврат исходного буфера |
| `wgtts.ui.widget` | Окно Tk, управление и анимация |
| `wgtts.ui.portrait` | Портрет и рамка как одно оформление |
| `wgtts.settings` | Проверка и сохранение настроек, пресеты |
| `wgtts.paths` | Встроенные ресурсы, пользовательские картинки и записываемые данные |

Tk работает в главном потоке. Консоль, обработка команд, наблюдение за чатом
и озвучка работают отдельно; фоновые потоки отправляют интерфейсу события.
Остановка озвучки обходит очередь команд. При выходе сбор отменяется с сохранением
уже прочитанного, затем возвращается исходный экран консоли.

## Установка и проверки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m build
```

Editable-установка связывает окружение с исходниками. Изменения Python-файлов
доступны сразу после перезапуска программы. Лаунчер автоматически обновляет
установку при изменении `pyproject.toml`.

Тесты в `tests/chat`, `tests/speech` и `tests/ui` повторяют структуру пакета.
Они не запускают живые задачи Applio. Отдельные ручные проверки вызываются явно
из корня репозитория:

| Проверка | Команда |
| --- | --- |
| Доступность UI Automation в открытом ChatGPT | `python -m tools.inspect_uia` |
| Восстановление текста, курсора и режимов консоли | `python -m tools.check_console_screen` |
| Виджет без Applio и звука | `python -m tools.preview_widget --silent --seconds 10` |
| Короткий реальный синтез | `python -m tools.test_speech` |
| Отмена своей тестовой задачи Applio | `python -m tools.test_cancel` |
| Очистка временных файлов своей задачи | `python -m tools.probe_storage` |

Учебный прототип находится в `tools/legacy/prototype.py` и не входит в рабочий пакет.

## Ресурсы и данные

Изображения входят в wheel из `src/wgtts/assets`. Путь `assets/arthas.gif` в
настройках — стабильный псевдоним встроенного портрета; старые настройки и пресеты
продолжают работать. Пользовательские относительные пути считаются от корня
исходников, а при установке wheel — от текущей папки запуска. Абсолютные пути
тоже поддерживаются.

В исходниках записываемые файлы остаются в `data/`; установленный wheel использует
`%LOCALAPPDATA%\WinGPT TTS`. Код не пишет настройки и историю в `site-packages`.
Локальные настройки, история, аудио, снимки диагностики и резервные копии исключены
из Git и из исходного архива пакета.

Зависимости перечислены только в `pyproject.toml`. `requirements.txt` оставлен
как совместимый вход для `pip install -r requirements.txt` из корня проекта.
